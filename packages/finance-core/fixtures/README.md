# Shared synthetic fixtures

Synthetic data only — never real statements.

These files pin down the behavior the TypeScript port (`../src`) must share with the
Rails app (`app/services/finance/*.rb`):

| File | What it pins down |
|---|---|
| `categorize-cases.json` | Inputs for `merchant_key` and `Categorizer#categorize` |
| `statements/*.csv` | Inputs for `StatementImporter` parsing (rows, categories, closing balance) |
| `statements/errors.json` | Malformed files and the Rails error key each must raise |
| `pdf/*.txt`, `pdf/errors.json` | Page text (pages split by form feeds) for `PdfStatementExtractor`: rows, warnings, closing balance, auto-import |
| `expected/*.json` | **Generated by Ruby** from the Rails code — the source of truth |

Regenerate the expected output after changing Rails rules (uses the test environment,
reads no database rows and writes nothing):

```sh
RAILS_ENV=test bin/rails runner packages/finance-core/fixtures/generate_expected.rb
```

Then run `npm test` in `clients/universal`. Any difference between Ruby and TypeScript fails.
The same statements are also checked against Rails' dashboard totals by
`test/services/finance/shared_fixture_parity_test.rb`.
