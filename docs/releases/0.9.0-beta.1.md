# BillieWeather 0.9.0-beta.1 (macOS, personal use)

Apple Silicon, macOS 11 or later (tested on 27.2). Ad hoc signed, not notarized: for your own Mac, not for distribution.
This build signs in through the servers on this Mac (`localhost:3000` and `localhost:8100`), like the installed 0.1.0. Other servers need another build (`BILLIE_API_URL`, `BILLIE_IDENTITY_URL`).

## New since 0.1.0

- **Undo and Redo** for every edit of the book: amounts, dates, merchants, descriptions, categories, notes, tags, types, accounts, batch edits, trash, imports, AI suggestions, budgets, schedules. Buttons at the top, ⌘Z and ⇧⌘Z. They survive a restart. Undoing 25 or more entries asks first. Permanent deletion stays permanent and leaves no copy in the history. [How it works](../architecture/editing-history.md).
- Feature Library, new Transactions overview, Add & Sync, quick entry.
- Sign-out is enforced by the server; other devices can be signed out.
- Damaged or newer databases are explained and never replaced by an empty one. A second copy of the app does not open.
- Imported amounts and dates remain evidence and cannot be edited.

Not undoable: merging databases, website downloads, schedules posting by themselves. The website has no redo.

## Database compatibility

| | |
| --- | --- |
| 0.1.0 (the copy installed on 2026-11-17) | schema 9 |
| 0.9.0-beta.1 | schema 10: three new tables and triggers; no existing column or value changes |
| Upgrade 9 → 10 | automatic at first open, per database, in one transaction |
| Going back | 0.1.0 refuses a schema 10 database and changes nothing in it |
| Backup files | 0.1.0 backups restore in 0.9; 0.9 backups are refused by 0.1.0 ("newer version") |

Before the upgrade the app copies every database next to itself (`billieweather.db.pre-v10-<time>.bak`, with `-wal`). If that copy fails, nothing is opened.

## Install

1. Open the DMG and drag BillieWeather to Applications.
2. First opening of a build that is not notarized: right-click, Open. If macOS refuses: System Settings › Privacy & Security › Open Anyway.

## Upgrade from 0.1.0

1. In 0.1.0: **Data › Back up** every database to a file you keep. Check that the file opens under Restore.
2. In 0.1.0: **sign out**. Two ad hoc builds share no signing identity; without this macOS may ask for the keychain.
3. Quit (⌘Q). Check in Activity Monitor that no BillieWeather is running.
4. Copy the whole folder `~/Library/Application Support/com.billieweather.client` to another place. This is the copy to go back to.
5. Move `/Applications/BillieWeather.app` to another folder instead of deleting it.
6. Drag in the new app, open it, sign in. Compare entry counts and account balances with 0.1.0.

## Go back to 0.1.0

Entries made in 0.9 are not in 0.1.0 afterwards. Export or back them up first.

1. Quit 0.9 and move it aside. Put 0.1.0 back.
2. Rename `~/Library/Application Support/com.billieweather.client` (do not delete it), and put the copy of step 4 above in its place. Without that copy: in the folder, move `billieweather.db`, `-wal`, `-shm` aside, then copy the newest `billieweather.db.pre-v10-….bak` to `billieweather.db` (and its `-wal` to `billieweather.db-wal`) and delete `billieweather.db.schema`.
3. Open 0.1.0 and compare counts.
