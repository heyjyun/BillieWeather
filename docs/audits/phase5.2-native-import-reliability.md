## 1. 执行摘要

两个原生阻塞项都找到了根因。文件选择器不是应用缺陷，未改动选择器代码。OCR 是首次使用时的模型编译被 18 秒截止时间打断，已改为单独、有限时的准备步骤。CSV、扫描 PDF 和收据在签名 QA 包的真实 GUI 中走完选择、识别、审阅、确认、SQLite 持久化和重启校验。途中另发现 macOS 包从未带上 Tesseract 回退引擎，已修复并在 WKWebView 中实测。

## 2. 文件选择器根因：PASS（应用），Phase 5.1 现象来自自动化方式

对文件名文本单元执行 `AXPress` 会返回成功，但不产生选择回调，Open 保持 disabled。这个现象可在两处按需复现，分别是纯 AppKit 对照程序和 BillieWeather。对行设置 `AXSelected`，或真实鼠标单击、双击，则 Open 立即可用并成功打开。因此高亮不等于选中。没有证据支持更换选择器、扩大权限或改动过滤器，所以没有改。Phase 5.1 的具体操作日志未保留，归因到该手势是根据相同现象的推断。

过程中纠正的测试错误有三处。对照程序因默认 macOS 28 部署目标无法启动（-10825）。驱动把 Dock 的透明覆盖层误判为遮挡。驱动曾匹配到页面内同名文字。三者都不计为产品失败。

## 4. Apple Vision 根因：PASS（已修复）

- 首次 `perform` 为 34–54 秒，随后各次 0.07–0.23 秒。占用时间在 `ANECompilerService` 编译模型。
- 同一二进制换进程名即冷启动（30.2 秒），原名仍为 0.44 秒。已打包应用按 Bundle 标识和系统版本缓存。同标识换新二进制仍为热（0.30 秒），普通更新不触发。早期以命令行程序得出的“更新即冷启动”结论已更正。
- 冷标识先在 5 秒终止，随后两次 18 秒操作均超时，未中断的准备 33.9 秒完成，之后 0.45 秒。这复现了 Phase 5.1 的连续超时。
- 冷启动并发排队，3 个进程分别为 49.0、60.2、71.6 秒。
- 指定 CPU 计算阶段仍为 33.8 秒，不能作为绕过方法。Swift/Rust FFI、线程和内存所有权没有发现缺陷，独立 Swift 程序同样复现。

修复内容如下。一个共享准备进程，上限 180 秒，每次运行最多 2 次尝试。请求在原有 18 秒截止时间内等待，到时交给端上 Tesseract，不会终止准备。worker 自带看门狗，应用退出或崩溃时自行结束。没有提高识别超时。未识别的 `--billie-*` 参数现在以退出码 2 拒绝。

**另一处缺陷（已修复）**：macOS 构建排除了 Tesseract 文件，原生回退此前不可能成功。安装包由 8 MB 增至 18 MB。
