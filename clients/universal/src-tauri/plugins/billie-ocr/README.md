# tauri-plugin-billie-ocr

On-device OCR for BillieWeather's mobile builds, exposed as the Tauri command
`plugin:billie-ocr|recognize`.

| Platform | Engine | Code |
|---|---|---|
| Android | ML Kit Text Recognition v2, **bundled** Chinese-script model (`com.google.mlkit:text-recognition-chinese:16.0.1`) | `android/src/main/java/app/billieweather/ocr/OcrPlugin.kt` |
| iOS | Apple Vision via the shared `src-tauri/ocr-apple/BillieVisionOCR.swift` (symlinked into `ios/Sources/`) | `ios/Sources/OcrPlugin.swift` |
| Desktop | none: the command always fails with `"unsupported_platform"` (desktop uses other engines) | `src/desktop.rs` |

## Command

```ts
invoke("plugin:billie-ocr|recognize", { image: base64PngOrJpeg, page: 1, languages: ["en", "zh-Hans", "zh-Hant"] })
```

It resolves with the shared `OcrResult` contract (`packages/finance-core/src/universal/ocr.ts`),
passed through from the native side unchanged. Per-page problems (`decode_failed`, `too_large`
(over 60,000,000 pixels), `recognition_failed`) come back inside `errors`. The promise rejects only
when the call itself fails: `unsupported_platform` (desktop), invalid arguments, or a bridge error.
`cancelled` is never produced, because cancellation is not implemented.

Android coordinates: the bitmap is decoded, EXIF orientation is applied by physically
transforming it with a `Matrix`, and any detected extra quarter turn is applied the same way.
ML Kit then gets `rotationDegrees = 0`, so its boxes are already in the upright frame. Boxes are
scaled back to full-resolution pixels if the bitmap was subsampled (inputs over 16 MP are
decoded with `inSampleSize`). `rotation` is the detected extra clockwise turn, not the EXIF
turn, which matches the Apple adapter.

## Verification status (be precise about this)

Compiled and checked on macOS (arm64, Command Line Tools only, no Xcode/JDK/Android SDK):

- `cargo check` and `cargo clippy` in this directory pass (desktop `cfg`). The build script
  generated `permissions/autogenerated/**` (`allow-recognize`, `deny-recognize`).
- The app crate was checked in a scratch copy with this plugin wired in (path dependency,
  `.plugin(tauri_plugin_billie_ocr::init())`, `"billie-ocr:default"` capability).
- `swiftc -parse` passes for `ios/Sources/OcrPlugin.swift`, `ios/Sources/BillieVisionOCR.swift`
  (through the symlink) and `ios/Package.swift`.
- `swiftc -typecheck` of `OcrPlugin.swift` + `BillieVisionOCR.swift` passes against a hand-written
  **stub** of the Tauri Swift API (signatures copied from tauri 2.12.5 `mobile/ios-api`), on
  macOS. This is not an iOS build.
- The component names in `android/src/main/AndroidManifest.xml` were read from the manifests
  inside the published `transport-backend-cct` 2.3.3 / 5.0.0 and `transport-runtime` 2.2.6 / 5.0.0 AARs.

NOT compiled or tested:

- `src/mobile.rs` (`cfg(mobile)`): no Android or iOS Rust targets are installed here.
- `OcrPlugin.kt` and the Gradle module: no JDK or Android SDK. It was written against the
  tauri 2.12.5 Android API sources and the ML Kit API reference.
- The iOS Swift package against the real Tauri package and iOS SDK.
- Whether SPM/Xcode follows the `BillieVisionOCR.swift` symlink in the Tauri iOS build (it
  should; check it on the first iOS build).
- Assumptions to verify on a device:
  1. The bundled Chinese-script model also reads Latin script (en/es). Google's language page
     does not say so. If it doesn't, add `com.google.mlkit:text-recognition` and choose a
     recognizer per request.
  2. The bundled model reports real `getConfidence()` values. If it returns 0 for every line,
     the plugin reports `null` and adds `line_confidence`/`word_confidence` to `unsupported`.
  3. Telemetry: the merged APK manifest no longer contains `CctBackendFactory`, and a network
     capture during OCR shows no traffic to Google logging endpoints. See the TODO in the
     manifest. This is a workaround, not a documented Google opt-out.
  4. Memory on low-end devices for large scans. The decode budget is 16 MP, and up to three
     bitmaps are held during the rotation search.
