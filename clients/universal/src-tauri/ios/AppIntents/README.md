# Siri and Shortcuts (App Intents) for iOS

`BillieWeatherIntents.swift` adds three App Intents and their Siri phrases:

| Intent | Siri / Shortcuts phrase (examples) | Opens |
|---|---|---|
| `ScanReceiptIntent` | "Scan a receipt with BillieWeather" | `billieweather://capture/receipt`: receipt capture (camera / upload) |
| `AddExpenseIntent` | "Add an expense to BillieWeather" | `billieweather://capture/expense`: the new expense form |
| `OpenBillieWeatherIntent` | "Open BillieWeather" | `billieweather://open` |

Every intent only opens the app on a screen (`openAppWhenRun = true`, then the app opens its own link).
No intent reads, saves or sends financial data, and a link never carries data: `src/services/deepLink.ts`
accepts only the three screen names above and ignores everything else.
`ScanReceiptByLinkIntent` is an optional iOS 18 variant built on `OpenURLIntent`. It is hidden from Shortcuts (`isDiscoverable = false`).

## Status

- **Compiles**: the file type-checks against the macOS SDK from the Command Line Tools (AppIntents exists on macOS 13+), in Swift 6 language mode, with no warnings:
  ```sh
  cd clients/universal/src-tauri/ios/AppIntents
  xcrun swiftc -typecheck -swift-version 6 -sdk "$(xcrun --show-sdk-path --sdk macosx)" -target arm64-apple-macos13.0 BillieWeatherIntents.swift
  ```
  The iOS SDK is not installed (no Xcode), so it has **not** been compiled for iOS.
- **Not verified**: Siri, the Shortcuts app and the phrases were never run. The App Shortcuts metadata (phrases) is extracted by Xcode's build step (`appintentsmetadataprocessor`), which needs full Xcode.
- **Deep links**: `tauri-plugin-deep-link` is in `Cargo.toml` and `src/lib.rs`, the `deep-link:default` permission is in `capabilities/default.json`, and the scheme is set in `tauri.conf.json`:
  ```json
  "plugins": { "deep-link": { "mobile": [{ "scheme": ["billieweather"], "appLink": false }], "desktop": { "schemes": ["billieweather"] } } }
  ```
  On iOS, the plugin's build step writes `CFBundleURLTypes` (scheme `billieweather`) into the generated `Info.plist`.

## Adding the intents to the iOS app (needs a Mac with full Xcode)

1. Generate the Xcode project once: `cd clients/universal && npm run ios:init`. This creates `src-tauri/gen/apple/` with an Xcode project and the app's iOS target. Tauri names it `<name>_iOS`, for example `billieweather_iOS`. The names below assume that; use the generated ones.
2. Run `npx tauri ios build` (or `ios dev`) once, so the deep-link plugin writes the URL scheme into `src-tauri/gen/apple/billieweather_iOS/Info.plist`. Check that the file now contains:
   ```xml
   <key>CFBundleURLTypes</key>
   <array><dict>
     <key>CFBundleURLName</key><string>com.billieweather.client</string>
     <key>CFBundleURLSchemes</key><array><string>billieweather</string></array>
   </dict></array>
   ```
   If it is missing, add it by hand: Xcode › target `billieweather_iOS` › Info › URL Types › +, Identifier `com.billieweather.client`, URL Schemes `billieweather`.
3. Open `src-tauri/gen/apple/billieweather.xcodeproj` in Xcode. Drag `src-tauri/ios/AppIntents/BillieWeatherIntents.swift` into the project navigator:
   - Untick "Copy items if needed", so the file stays here, under version control.
   - Under "Add to targets", tick **only `billieweather_iOS`** (the app target, not a separate extension: intents with `openAppWhenRun` must live in the app).
4. Target `billieweather_iOS` › General › Minimum Deployments: iOS **16.0** or later. The ready-made phrases (`AppShortcutsProvider`) need iOS 16.4. Swift Language Version: 5 or 6, both compile.
5. Signing & Capabilities: choose your Apple Developer team. App Intents need no extra entitlement, and there is no "Siri" capability to add: that one is only for the older SiriKit intents.
6. Build and run on a device or simulator. Then try "Hey Siri, scan a receipt with BillieWeather", or the Shortcuts app › App Shortcuts › BillieWeather. The app should open on *Capture a receipt*.
7. `gen/apple` is regenerated by `ios:init`. If you regenerate it, repeat step 3, or add the file to `project.yml` (XcodeGen) under the iOS target's `sources`.

## Languages

The phrases are English only. To offer them in the app's other languages (zh-Hans, zh-Hant, ja, ko, es), add an
`AppShortcuts.xcstrings` string catalog to the same target and translate each phrase. Every phrase must keep
`${applicationName}`. Not done yet, because it can only be checked in Xcode.

## Desktop

The same `billieweather://` links open the app on macOS (the scheme is in the bundle's `Info.plist` when the app is
built with `npm run desktop:build`; `desktop:dev` does not register it). On Windows and Linux, the OS starts the app with the link as an argument, and
`getCurrent()` reads it. A second link while the app is already open starts a second instance, unless
`tauri-plugin-single-instance` (feature `deep-link`) is added. That plugin is not added yet.
